第 1 步：先把四个词连起来

状态是对象当前所处的位置；事件是刚发生的事情；转换表列出允许路径；下一状态是查表结果。

当前状态waiting
事件start
查允许路径waiting + start
下一状态running

先不写代码：如果当前是 done，事件是 start，而转换表没有这个组合，程序应该做什么？

需要方向提示时展开

转换表没有列出的组合，不应猜测新的状态。

第 2 步：把转换表写成 Python

Python 可以用二元组 (current, event) 作为字典键。这里的重点不是背语法，而是让允许路径成为显式数据。

transitions = {
    ("waiting", "start"): "running",
    ("running", "finish"): "done",
}

业务新增：waiting 可以 cancel，running 不能 cancel。请分别说明转换表需要增加什么，以及为什么 running + cancel 必须拒绝。

今天的问题

后台任务为什么不能从任何状态随意进入下一状态？完成后，你会把允许行动写成一张可检查的转换表。

一、先想象一个真实任务

新任务最初是 waiting。Worker 领取后变成 running，成功后变成 done。状态不是说明文字，而是后续行动的条件。

如果已经 done 的任务再次收到 start，继续执行可能制造重复副作用。因此“表里没有”应当意味着拒绝。

展开任务一 · 只做预测

done + start 应怎样处理？

二、把业务规则变成数据

二元组把当前状态和事件绑成一个键，字典把这个键映射到下一状态。这样代码不需要散落很多互相覆盖的判断。

key = (current, event)
if key not in transitions:
    raise ValueError("invalid transition")
return transitions[key]
