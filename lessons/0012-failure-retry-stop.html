问题一 · 第 1/7 步 · 定向

先把 retry 里的量分开

现在只做：只认出量的含义，不写代码。一次操作失败以后，程序先判断有没有下一次执行机会；只有有机会时，才会计算等待时长。
attempt · 执行序号当前正在执行第几次 operation()；第一次执行是 1。
重试序号第一次执行失败后再执行，才叫第一次重试；因此第一次重试对应 attempt=2。
max_attempts · 执行上限整次操作最多执行多少次，包括第一次执行。
delay · 等待时长下一次执行前等待多久；本题使用抽象时间单位。
是否继续最后一次失败没有下一次执行机会，因此不调用 sleep_fn。
等待策略固定等待每次相同；指数退避根据 attempt 计算候选时长。
本题不处理：两个请求是不是同一次业务操作，也不检查批量数据是否合法。先建立“执行次数、重试次数、执行上限、等待时长”的语义区别。

    pass  # 保持不变：pass 是合法语句，类名本身就是失败分类标签

    pass  # 保持不变：这里只建立分类，不增加额外行为

def run_with_retry(operation, max_attempts: int, sleep_fn):  # 接收操作、尝试上限和可替换的等待函数

第 1/23 步 · 会话地图

本会话中文术语与量的定义

先按中文含义理解；每个词都对应具体代码责任，数字也说明单位和发生时机。

attempt · 执行序号
当前正在执行第几次 operation()；第一次执行是 1，第一次重试是 2。
max_attempts · 执行次数上限
整次操作最多执行多少次，包括第一次执行。
delay · 等待时长
下一次执行前等待多久；本会话使用抽象时间单位。
固定等待策略
每次需要重试时都传入相同的等待时长，例如每次都是 1。
指数退避 exponential backoff
根据当前执行序号计算候选等待时长，例如 1、2、4、8；候选值不等于一定发生的等待。
操作身份 operation identity
标识一次业务意图的稳定值。
原子预留 atomic reservation
不可被并发打断地取得唯一创建资格。
唯一约束 unique constraint
由数据库原子拒绝重复值。
行级规则 row-level rule
只依赖当前一行资料。
批次级规则 batch-level rule
依赖多行比较或整批汇总。
累计错误 error accumulation
继续执行独立规则并保存多个错误。
有界变化 bounded change
只改变一个明确条件，先观察新案例，再说明稳定结构；开放式迁移留到后续阶段。
控制流 control flow
程序实际执行、跳转、返回和抛出的顺序。
接口约定 interface contract
调用者可依赖的输入、输出、异常和副作用规则。
