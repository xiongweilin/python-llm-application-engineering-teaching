第 2 步 · 已有能力地图

十条记录可以压缩成四组能力

现在只做：先看四组标题，尝试回忆每组内部的区别；再读说明校正。
LR 0001–0002、0010

规则怎样判断

函数按固定规则把输入转为输出；规则必须放在能看见所需资料的范围；累计错误与首错即停是不同接口约定。

LR 0003–0005

任务怎样安全推进

状态限制跨时间行动，锁解决同时领取，短事务减少占用，但必须配套陈旧任务恢复。

LR 0006–0007

失败与重复怎样受控

有限重试处理暂时失败，等待间隔拉开故障窗口；幂等键标识操作，数据库唯一约束守住并发落库。

LR 0008–0009

判断怎样落到代码

HTTP 边界、流程编排、单行规则分属不同模块；方法链会传递返回值，递归会再次调用自身，可变操作可能产生外部可见副作用。

这四组不是四套系统。它们分别回答：判什么、何时能做、失败后怎么办、代码放哪里。

范围决定规则位置

只看一行的函数能检查价格，却不能可靠判断整批重复。问题不在语法，而在函数拥有的资料范围。

状态不替代锁

状态保存跨时间事实；两个 Worker 同时读取旧状态时，仍需要锁或原子更新解决瞬间竞争。

短事务不等于自动恢复

提前保存“处理中”并释放锁能提高并发，但进程随后崩溃会留下陈旧任务，因此恢复是新增责任。

幂等预查不替代唯一约束

应用预查能改善流程；并发请求仍可能同时看到“不存在”，最终边界必须由数据库唯一性守住。

第 1/7 步 · 定向

本会话中文术语

只保留连接十条记录时会反复用到的词；旧页面中的局部细节仍可按需查阅。

资料范围 data scope
一条规则作出可靠判断时必须同时看见的资料集合。
控制流 control flow
程序实际执行、跳过、中断和返回语句的顺序。
接口约定 contract
调用者与被调用代码共同依赖的输入、输出、错误与副作用规则。
状态 state
保存跨时间事实，并限制当前允许行动的值。
锁 lock
在同一时间窗口阻止竞争者同时操作共享对象的机制。
事务 transaction
把一组数据库变化作为完整单位提交或回滚的边界。
陈旧任务 stale task
长期停留在处理中、但实际执行者已经无法继续的任务。
有限重试 bounded retry
只在明确次数或时间范围内再次尝试，并配合停止条件。
等待间隔 backoff
拉开相邻尝试的时间，避免全部落在同一个故障窗口。
幂等键 idempotency key
标识同一次操作身份、使重发可被识别的稳定值。
唯一约束 unique constraint
由数据库在最终写入边界阻止相同键产生多条记录。
副作用 side effect
函数返回之外，外部仍可观察到的状态变化。
方法链 method chaining
在前一次调用的返回值上继续调用下一个方法。
模块职责 module responsibility
一个模块应拥有的判断资料与变化责任。
