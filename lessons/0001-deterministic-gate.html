程序怎样决定“通过”还是“拦住”

这一课不要求你懂英文，也不要求你懂 Python 写法。我们只理解一件事：程序收到一行商品资料后，会按照事先写好的规则做检查。

先放心

页面中的英文只是程序使用的固定名字。第一次看到时，我都会给出中文意思。现在不需要背，也不考拼写。

1. 把程序想成门口检查员

一行商品资料来到门口。检查员逐项检查：编号对不对、名称有没有、品类是否允许、价格和库存是否合理。

① 商品资料
程序的“输入”
② 按固定规则检查
③ 写出错误清单
程序的“输出”之一
④ 决定
通过或拦住
错误清单是空的

说明没有发现问题，这一行可以继续。

错误清单里有内容

说明至少有一个问题，这一行被拦住。

2. 本课只认识四个词

函数
function 一段可以反复使用的小任务。这里的任务是“检查一行商品资料”。
输入
input 交给函数处理的东西。这里就是一行商品资料。
输出
output 函数处理后交回来的结果。这里包括整理后的资料和错误清单。
列表
list 按顺序装多个项目的容器。错误清单就是一个列表，可以是空的，也可以装多个错误。

需要跨页查词时打开：跨会话中文术语总表。它是复习索引，不是作业。

3. 把中文意思和源码名字对上

validate_source “检查原始资料”。这是检查函数的名字。
row “一行资料”。这是函数收到的输入。
errors “错误清单”。这是检查过程中收集的错误。
imported “已通过入口检查”。这是程序内部使用的状态名字。
validation_failed “检查未通过”。也是程序内部的状态名字。

真实源码写得很紧凑。为了先看懂意思，我们把它展开成等价的中文思路：

如果 错误清单里有内容：
    状态 = “检查未通过”
否则：
    状态 = “已通过入口检查”

这里最重要的不是英文，而是判断规则：错误清单有没有内容。

4. 为什么不让人工智能先判断？

SKU 格式、允许品类、价格范围和库存范围都是明确规则。明确规则由普通程序检查，结果稳定、便宜、可复查。只有通过这些规则的资料，才有资格进入后面的文案生成人工智能。

因此：人工智能可以帮助写文案，但没有权忽略入口错误。
