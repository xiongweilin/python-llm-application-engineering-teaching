为什么重复点击不会创建两个导入任务？

有限重试处理后台程序自己的再次尝试；这项记录转向客户端重发：用户双击或网络超时后再次提交时，怎样保证同一次导入只产生一个任务。

本课新词：幂等

幂等（idempotency）表示同一个业务操作重复请求多次，最终仍只产生一次业务效果。

1. 把幂等键想成订单编号

付款请求发出去后，页面没有及时响应。用户不知道是否成功，于是再次点击。如果两次请求带着同一个订单编号，系统应当理解为“同一次付款的重发”，而不是收两次钱。

相同幂等键

import-001 再次出现，表示同一次导入请求重发。

系统返回已经存在的导入任务。

不同幂等键

import-001 与 import-002 表示两次不同操作。

即使 CSV 内容相同，也可能创建两个任务。

核心原则：幂等键标识“是不是同一次业务操作”，不是用来判断两个文件内容是否相同。

2. 第一层：先查有没有同一个键

收到导入请求
键是 import-001
查询数据库
是否已有 import-001
已经存在
返回原任务
响应标记
reused = true

这样，顺序到达的第二次请求不会重新解析 CSV，也不会创建第二批商品。

3. 为什么还需要数据库唯一约束？

如果两个请求几乎同时到达，可能发生：

请求 A 查询：没有 import-001
请求 B 查询：也没有 import-001

请求 A 准备创建
请求 B 也准备创建

单靠“先查询”仍可能重复。数据库因此规定：幂等键在整张任务表中必须唯一。

保护层作用
应用先查询常见重复请求可以快速返回原任务
数据库唯一约束两个请求同时创建时，最终也只允许一个相同键写入
冲突后的查询创建失败的一方撤销本次写入，再读取已经成功的原任务

4. 当前项目怎样表现？

第一次提交 import-001：
    创建任务 → reused = false

第二次提交 import-001：
    返回同一个任务 → reused = true

两次的 run_id 相同

run_id 是导入任务自身的编号。返回相同编号，说明第二次没有创建新任务。
