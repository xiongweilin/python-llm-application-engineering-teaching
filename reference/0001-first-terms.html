跨会话中文术语总表

这是跨会话复习索引，不是当前会话的替代品。每个正式会话页面下方都有只服务于本次学习的中文术语表；总表用于之后横向查找。

阅读顺序永远是：先明白中文意思，再认出源码里的固定名字，最后才学习怎样自己写。

程序的基本组成

程序
program
让计算机按照一组步骤完成事情。例：读取商品资料，检查错误，保存结果。
代码
code
程序员写给计算机的具体指令。Python 是书写这些指令的一种语言。
源代码
source code
项目里由程序员编写、实际组成程序的代码，通常保存在一个个文件中。
数据
data
程序要处理的内容。例：商品编号、名称、价格、库存。
对象
object
程序中可以被引用、读取或操作的具体事物。字符串、列表、字典和后台任务记录都可以作为对象来理解。
函数
function
一段可以反复使用的小任务。validate_source 的任务是检查一行商品资料。
变量
variable
程序里用名字指向某个数据的位置。errors 指向错误清单。

函数怎样工作

输入
input
交给函数处理的东西。row 是一行商品资料。
输出
output
函数完成后交回的结果。整理后的商品资料和错误清单。
返回
return
函数把结果交回调用者的动作。
调用
call
要求某个函数现在执行一次。导入流程会调用检查函数。

装数据的方式

字符串
string / str
一段文字。"办公用品"、"DESK-001"。
列表
list
按顺序装多个项目的容器。错误清单可以装零个、一个或多个错误。
字典
dictionary / dict
保存“键 → 值”映射的对象。既可以保存 sku → DESK-001，也可以保存“状态与事件 → 下一状态”。
元组／二元组
tuple
按顺序放置若干值的不可变对象。包含两个值时可称二元组；(current, event) 可以作为复合字典键。

正式会话 1：状态与允许行动

事件
event
刚刚发生、可能触发状态变化的事情。start、finish、cancel。
转换表
transition table
列出允许的“当前状态 + 事件”组合，以及各自下一状态的规则表。
转换函数
transition function
接收当前状态和事件，返回下一状态或拒绝非法组合的函数。
部分函数
partial function
只对部分输入组合有结果；没有被定义的组合不应由程序猜测。
成员判断
membership test
用 in 或 not in 判断一个键是否存在于容器中。
控制流
control flow
程序语句实际执行、跳过、中断和返回的顺序。
异常
exception
正常返回不能表达当前结果时，中断当前路径并向调用者报告问题的机制。
值错误
ValueError
输入类型可能正确，但具体值或值的组合不符合接口约定。
类型标注
type hint
写给人和工具看的接口提示；Python 默认不会只凭标注自动强制类型。

正式会话 2：重试、防重复与批处理

暂时错误
TemporaryError
原因可能随时间消失，因此允许在预算内等待后再次尝试。
永久错误
PermanentError
当前条件不变时重试通常无效，应立即抛出并停止。
尝试预算
retry budget
自动执行最多允许发生的次数或时间范围。
停止条件
stop condition
明确规定何时不得继续自动尝试；停止是策略的一部分，不是程序放弃工作。
重新抛出
re-raise
在 except 中使用单独的 raise，让原异常继续向调用者传播。
依赖注入
dependency injection
把等待等外部行为作为函数参数传入，便于替换、记录和测试。
指数退避
exponential backoff
按 1、2、4 等方式逐次延长等待，避免持续冲击故障服务。

项目里常见的词

批次
batch
一次一起送进程序处理的一组资料。一个 CSV 文件中的多行商品可以组成一个导入批次。
处理范围
scope / context
当前函数实际能够看见和使用的数据。只收到一行，就看不见其他行。
职责
responsibility
某个函数或模块应该负责完成的事情。规则应放在能够看见所需数据的位置。
重复
duplicate
同一个应当唯一的内容出现多次。同一批商品中出现两个相同 SKU。
检查
validate
按照明确规则确认数据是否合格。
状态
state / status
记录对象当前处于什么位置，并作为后续行动能否发生的条件。imported 表示已通过入口检查。
状态变化
state transition
一件资料完成某一步后，从一个状态进入另一个状态。从“等待文案”变成“正在生成文案”。
流程
workflow / process
一件事情按照先后顺序经过的多个步骤。
错误
error
程序发现的不合规则之处，或执行时发生的问题。
模块
module
把同一类职责放在一起的 Python 文件。validation.py 放检查规则。
入口
entry point
外部请求进入程序的第一层。它负责接收和回应，不应拥有全部业务规则。
编排
orchestration
按照顺序调用多个职责模块，把它们组织成一条完整流程。
职责边界
responsibility boundary
明确某个模块应该负责什么、不应该负责什么；需求应改在真正拥有该规则的位置。
后台工作程序
worker
不直接面对用户、在后台领取并处理任务的程序。
锁
lock
数据库暂时标记一行正在被某个程序处理，避免另一个程序同时修改同一行。
跳过已锁记录
skip locked
遇到已经被别的程序锁住的记录时，不等待，也不重复领取，而是寻找下一条可处理记录。
确认保存
commit
把本次数据库修改正式保存；当前项目在确认状态变化后释放对应的行锁。
事务
transaction
数据库把一组相关操作当成一个整体处理；最终确认保存，或在失败时撤销。
外部调用
external call
当前程序向另一个服务发出请求并等待结果。后台程序向 Dify 请求生成商品文案。
超时
timeout
外部请求等待超过设定时间仍未完成，程序停止继续等待并把它当作失败。
陈旧任务
stale task
任务长期停在“正在处理”，但负责它的程序可能已经退出，需要被识别并重新排队或人工处理。
重试
retry
一次处理失败后，在条件允许时再次尝试。
尝试次数
attempt count
记录已经执行过多少次，用来限制重试不能无限继续。
暂时失败
transient failure
原因可能很快消失的失败。短暂网络超时或外部服务临时不可用。
终止失败
terminal failure
达到重试上限后停止自动尝试，保留错误等待人工检查。
退避
backoff
每次重试前先等待一段时间，通常逐次延长，避免连续快速请求给故障服务增加压力。
幂等
idempotency
同一个操作重复请求多次，最终只产生一次业务效果。
幂等键
idempotency key
调用方为一次业务操作提供的稳定编号。相同编号表示“这是同一次操作的重发”。
唯一约束
unique constraint
数据库保证某个值在整张表中不能重复。一个幂等键最多对应一个导入任务。
竞争情况
race condition
两个程序几乎同时检查和修改同一资源，执行先后不同可能产生不同结果。
人工智能大模型
LLM
擅长生成和理解文字，但结果不完全确定，所以不能绕过固定规则。
企业资源系统
ERP
管理商品、库存等业务资料的系统；本项目使用 Odoo 作为演示 ERP。
