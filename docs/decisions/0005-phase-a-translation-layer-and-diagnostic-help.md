# 0005：阶段 A 建立教学语言到 Python 表达的翻译层

## 状态

已接受，2026-08-18。

## 背景

阶段 A 之前已经降低了空白页压力、增加了逐行旁注、语法卡和 editable locus，但学习者仍会在“控制流”“把变量和等待值对应起来”“等待表达式”“调整分支”等压缩说法处停住。问题不只是提示不明显，而是页面把以下多个动作压缩成了一个“修改代码”任务：理解现实规则、找到程序责任、定位代码、识别 Python 写法、判断是否需要修改以及实际输入。

学习者的现实逻辑理解通常强于程序结构识别，程序结构识别又强于 Python 表达熟悉度：

```text
问题逻辑理解 ≫ 程序结构识别 > Python 表达熟悉度
```

“以前学过 Python”只能说明可能恢复得快，不能证明 `pass`、`except`、函数调用、参数、表达式、`range`、`raise` 等当前仍然可调用。

## 决定

阶段 A 的所有正式任务统一经过：

```text
现实含义 → 程序责任 → 代码位置 → Python 写法 → 学生操作 → 运行验证
```

具体决定：

1. 每个第一次出现的术语必须标明来源：普通中文、程序概念、Python 语法、代码变量、标准技术术语或课程说法；先解释现象，再给名称和代码例子。
2. 代码阅读所需的语法解释默认可见；逻辑推理和完整答案继续分级隐藏。
3. 每道题分开记录问题逻辑、程序结构和 Python 表达三种难度，不用语法失败替代结构诊断。
4. 早期任务按“填槽位 → 改一行 → 改代码块 → 函数内定位 → 文件内定位 → 项目内定位”增加自由度。
5. 帮助固定为五类：题目让我做什么、改哪段代码、Python 怎么写、为什么这样改、参考答案。前四类不直接泄露尚未训练的判断。
6. 任务模板必须同时写出现实效果、程序责任、可编辑位置、保持不变的代码、当前 Python 写法和运行验证边界。

## 未采用的方案

- **继续只增加 syntax card：**只能补充写法，不能解释学习者为什么不知道题目语言、代码位置和程序责任。
- **让模型自行决定哪些词“直观”：**会把课程自创压缩词误当成标准术语，增加无效记忆负担。
- **用“教师示范 → 局部修改”覆盖全部早期任务：**仍然跳过现实含义、程序责任和 Python 表达之间的翻译层。
- **用一次 Python 语法诊断替代持续观察：**语法恢复是构造级、随任务变化的状态，不能用“曾经学过”或一次测验推断整套可调用性。

## 后果

- 正式会话页面需要增加翻译地图、术语来源标签和五类帮助入口；任务文案会变长，但减少了学习者猜测页面意图的隐性成本。
- 检查器仍只验证可运行行为；学习记录还需注明逻辑、结构和表达分别得到的证据。
- 阶段 A 前期的完整代码可以只读展示，输入限制在明确的 editable locus；后续根据真实行为逐步撤掉定位帮助。
- 会话 1 的复习页、会话 2 的当前页以及补充练习页共享这套语言协议；后续会话 3 也必须从该模板开始。
