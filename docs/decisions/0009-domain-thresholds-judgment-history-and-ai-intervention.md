# 0009：分领域阈值、判断版本轨迹与 AI 介入契约

## 状态

已接受，2026-08-18；扩展 0008，不改变当前正式会话 2 的页面内容。

## 背景

课程已经加入开放问题窗口和 Minimum Viable Judgment，但仍有四个需要明确的课程级风险：

1. 一个 Python/工程阈值不能代表概率、优化、序贯、RAG 或因果领域也已准备好开放判断；
2. 开放问题如果只问一次，会变成漂亮但没有学习作用的五分钟活动；
3. 强模型如果没有介入边界，可能在学生预测前给答案，或用高级解释掩盖基础缺口；
4. 最终综合项目如果强行要求每个理论工具都进入同一现实问题，会把适用性判断变成形式主义。

## 决定

### 1. MVJ 按领域独立定义

每个工作域都有自己的最低可判断能力链：

```text
Python/工程：现象 → 状态/规则/副作用/接口 → trace/测试/traceback → 修改或恢复
概率/统计：现象 → 随机变量/候选模型 → 假设/证据边界 → 后验、风险或校准
优化/决策：资源冲突 → 变量/目标/约束 → 求解/敏感性 → 行动或升级
序贯：当前状态/未来影响 → 转移/策略模型 → 价值/拥塞/后悔 → 策略或停止建模
RAG/Agent：失败现象 → 检索/生成/工具/权限分解 → trace/指标/人工证据 → 干预与评估
因果/可靠性：结果变化 → estimand/识别假设/数据生成 → 实验/DAG/回归 → 上线、停止或回滚
```

阈值按领域记录，不产生全局“已独立”标签。

### 2. 开放判断必须有版本轨迹

开放问题第一次形成 `J0`。相关知识会话之后再次取出同一问题，形成 `J1`、`J2`……每个版本至少记录：当前主张、主要不确定性、依据的新证据、改变的部分、保留的部分和下一步证据。这样判断循环有可见的纵向修正，而不是一次性讨论。

### 3. AI intervention contract

统一规则是：

> **学习者能力上升时，答案供给下降，问题空间供给上升。**

| 状态 | AI 角色 | 必须避免 |
| --- | --- | --- |
| 基础恢复 | 解释器、示例生成器、语法检索器、即时诊断器 | 在预测前给结构答案 |
| 重建与变式 | 教练、分层提示器、反例和故障生成器 | 把检查通过说成掌握 |
| 开放窗口 | 专家视角展开器、候选缺口地图、对抗提问者 | 替学生框定问题或选择最终判断 |
| 领域 MVJ 后 | 高水平讨论对象、候选映射生成器、对抗测试器 | 默认回到完整答案供给 |
| 超过当前基础 | 清楚标记超出范围，给最小前置缺口和未来地图 | 用大段高级内容遮蔽当前缺口 |

AI 必须先检查学生是否提交预测或当前判断，再决定解释、hint、反例、检索要求、开放讨论或暂缓回答；帮助级别和介入理由要可记录。

### 4. 最终综合项目的适用性判断

六组综合能力仍然需要证据，但每个理论工具先标记：

```text
适用：对象、假设和证据边界支持使用
不适用：说明为什么不能用于主问题，并选择邻近真实子问题
尚不确定：明确需要什么证据才能决定
```

学生不得为了满足形式清单强行加入 MDP、机制设计或因果调整。知道何时不应使用一个工具本身就是 Frame/Discriminate/Judge/Challenge/Revise 的重要证据。

## 未采用的方案

- **一个全局 MVJ 阈值：**会把某领域的熟练误传给其他领域，导致帮助撤除过早。
- **每个开放窗口只问一次：**没有版本回看，就无法看见判断因新证据如何修正。
- **让强模型默认尽量多解释：**高级答案供给会破坏预测、框定和判断权。
- **最终 rubric 强制所有理论工具进入同一问题：**会产生与现实无关的形式建模。

## 后果

- `SESSION-PAGE-CONTRACT.md` 增加分领域 MVJ、`J0 → J1 → ...` 判断版本和 AI intervention contract；当前会话页面不变。
- `NOTES.md` 将这些内容列为生成和调度约束；README、首页和路线页明确课程范围是 minimum operational models。
- `FINAL-CAPABILITY-CONTRACT.md` 保留六组最终能力，但要求每组提交适用性判断；不适用时使用邻近真实子问题。
