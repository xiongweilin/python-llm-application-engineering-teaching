# 0008：课程加入开放问题窗口与能力阈值切换

## 状态

已接受，2026-08-18。补充并扩展 0007；不改动当前正式会话 2 的页面内容。

## 背景

阶段 A 已经把“降低语法、定位和多未知量造成的无关摩擦，同时保留预测、重建、诊断、迁移和边界判断”落实为完整工作单元循环。这解决了学习者从局部语法恢复到完整代码结构的问题，但当前课程的总表述仍主要像一条单向路线：先代码所有权，再数学、模型、真实系统，开放判断可能直到后期才出现。

如果开放判断完全推迟，学习者在很长时间内看不到未来真实问题的形状，也不会练习识别“我现在缺什么证据”。另一方面，阶段 A 不能突然要求初学者设计完整分布式系统。需要一个低成本、非关口的中间层，以及一个由能力证据触发的教学模式切换。

## 决定

课程从现在起同时运行两个循环：

```text
技能循环：范例 → 重建 → 受控修改 → 迁移 → 说明稳定结构
判断循环：真实问题 → 当前判断 → 专家视角展开 → 标记缺口 → 有目的补基础 → 重新判断
```

每 2–3 个正式会话安排一次约 5 分钟的开放问题窗口。窗口要求学习者回答：

1. 现在会怎样判断；
2. 最不确定什么；
3. 看过少量专家方向后，最值得补什么。

窗口不计作正式能力关口，不要求正确，不自动生成学习记录。它的作用是建立未来认知地图，并把“不能判断”转成可行动的缺口。

课程增加 Minimum Viable Judgment（最低可判断能力）作为教学模式切换阈值，而不是毕业标准。某个工作域达到以下组合后，默认从完整范例转为行为契约驱动：

- 能读陌生但受控规模的函数或工作过程；
- 能追踪控制流、状态、数据和副作用；
- 能区分状态、规则、接口和副作用；
- 能按行为契约重建主要结构；
- 能诊断未见失败并寻找相应证据；
- 能说明稳定结构与可变参数；
- 一次无答案间隔回忆和一次陌生近邻任务仍然成立。

阈值后的默认流程是：

```text
行为契约 → 学习者先判断 → 实现或诊断 → 运行证据 → 按缺口补基础
```

若失败，按证据动态恢复脚手架，而不是永久保留或一次性撤掉所有帮助。调度启发式为：阈值前约 80% 能力形成/20% 开放窥视；刚跨阈值约 60%/40%；稳定迁移后约 30% 针对性补基础/70% 真实问题。

阶段 A 的 `R/T/P/M/D/X` 继续记录执行可靠性；阈值后的判断记录增加五类动作：`Frame`（界定问题）、`Discriminate`（区分候选）、`Judge`（基于证据选择）、`Challenge`（寻找反例和遗漏变量）、`Revise`（依据新证据改变表示或目标）。这组词是教师记录语言，不要求学习者背诵。

相似工作模式的迁移帮助按以下顺序撤除：

```text
教师标出稳定骨架/变化点
→ 学习者自己标出
→ 比较相似实现
→ 面对真实故障先判断是否仍应使用该抽象
```

## 未采用的方案

- **把开放判断推迟到最终项目：**学习者会缺少未来认知地图，也不会练习识别未知量和证据缺口。
- **在阶段 A 立即要求开放式系统设计：**会把判断训练误变成过早的架构负担，重新制造无关摩擦。
- **另造一套替代 R/T/P/M/D/X 的大评分系统：**执行可靠性和开放判断是两层证据，应连接而不是互相替代。
- **按固定课时切换教学范式：**能力不足的工作域需要恢复脚手架，成熟工作域应进入真实问题；切换必须由证据触发。

## 后果

- `NOTES.md` 将开放窗口和阈值切换列为阶段 A 之后所有会话的生成约束。
- 首页和路线页需要说明课程是“脚手架学习 ↔ 开放判断”的飞轮，而不是单向的技术清单。
