# 0004：有界变化先建立可观察映射，再修改表达式

## 状态

已接受，2026-08-18。

## 背景

会话 2 的指数退避任务原本把三件事压在一句话里：理解 `attempt` 的含义、把 `attempt` 和等待值对应起来，以及把等待表达式写进 `sleep_fn(...)`。学习者被要求“先配对，再修改表达式”，但页面没有定义“配对”是什么，也没有明确表达式位于哪一行、哪一对括号中；同一段代码里还同时出现注释行、`pass` 和真正的修改值，导致学习者在开始思考 retry 之前先猜题目位置。

## 决定

阶段 A 的有界变化统一采用：

```text
自然语言条件 → 可观察配对/映射 → 边界判断 → 唯一可编辑位置 → 运行验证 → 稳定结构解释
```

对于指数退避，页面先明确：

- `attempt` 表示当前已经执行到第几次调用；
- 若预算允许安排下一次重试，`attempt=1,2,3` 对应等待序列 `1,2,4`；
- `attempt == max_attempts` 仍然阻止最后一次失败后的等待；
- “表达式”是 `sleep_fn(...)` 括号内能够计算出一个等待数值的代码，唯一修改位置是该参数，不是注释、`pass`、循环或停止判断。

页面用表格选择题先检查映射，再给只读代码和一个表达式输入框。检查器把表达式重新嵌回完整源码，验证等待序列和停止边界。

## 未采用的方案

- **直接把自然语言要求放在整段可编辑代码上：**学习者必须同时定位题目、回忆语法和理解映射，无法判断失败来自哪一层。
- **只给“先配对”四个字：**没有定义配对对象、方向和边界，等于把新的隐含术语当成了教学指令。
- **只给最终公式：**会让学习者照抄 `2 ** (attempt - 1)`，却没有形成变量到等待值的可迁移映射。

## 后果

- 有界变化任务会比单纯代码编辑多一个小型映射检查，但它减少了错误的题目定位和术语解释成本。
- 后续任务可以复用同一模式：先列出输入/状态到输出/副作用的配对，再让学习者修改唯一局部表达式。
- 学习记录可以区分“映射理解正确”“表达式写法需要帮助”和“整体控制流被误改”三类证据。
