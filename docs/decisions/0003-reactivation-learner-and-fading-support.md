# 0003：阶段 A 按再激活型学习者提供分层帮助

## 状态

已接受，2026-08-18。

## 背景

学习者曾经学习过 Python，仍然能够判断递归与链式调用、可变与不可变副作用、首错即停与累计错误以及受限制的状态转换，但具体语法暂时无法稳定调用。当前困难更接近“结构记忆仍在、符号检索失败”，而不是典型初学者的概念空白。

如果把阶段 A 继续写成完整 Python 入门课，会浪费已有结构能力；如果完全删除语法帮助，又会把偶然的语法遗忘误判成程序理解失败。此前的示范优先和逐行旁注解决了空白页压力与来回翻找问题，但把具体答案直接写进任务旁注，会削弱预测、边界判断和局部诊断。

## 决定

阶段 A 采用“结构要求保持、语法摩擦降低、帮助逐步淡出”的再激活教学模型：

```text
结构诊断 → 按需语法唤回 → 真实修改 → 运行校正 → 结构迁移
```

具体规则：

1. 正式会话提供建议路径和完整讲解两种入口。建议路径约 12 个高价值动作，优先呈现预测、局部修正、有界变化和统一提交；完整讲解仍保留七步闭环的所有步骤。两种路径共享任务、检查器和能力证据。
2. 语法提示按构造单独记录并递减：先给语法卡，再给结构追问，再给具体定位，最后才给参考修改。语法卡的使用不等于能力已经独立形成。
3. 逐行旁注始终解释对象、输入/输出、控制流、副作用和放置原因；默认任务旁注不得直接写出 `if`/`elif`、`>`/`>=`、异常类型或等待公式等语义答案。具体答案只能在折叠提示或检查反馈中出现。
4. 预测、失败分类、状态追踪、责任边界和一个有界条件变化继续作为阶段 A 的真实证据。被降低的是无关的语法检索摩擦，不是程序结构要求。
5. 学习证据分开记录结构追踪、局部修改、条件迁移、帮助级别和学习者解释。阶段 A 的毕业条件是帮助减少后仍能稳定追踪、修改和解释，而不是完全不查资料。

## 未采用的方案

- **把阶段 A 改成完整 Python 语法复习课：**会重复已经具备的结构能力，也不能证明学习者能在真实代码中判断责任和副作用。
- **默认任务旁注直接给出修改答案：**能降低输入难度，却会把语义判断变成抄写，无法区分理解、记忆和照抄。
- **所有帮助都隐藏，要求一次独立完成：**会把符号检索失败误判为结构能力缺失，并重新制造空白页压力。
- **只保留建议路径而删除完整七步：**会损失必要的底层逻辑和复盘入口，因此只折叠低摩擦解释，不删除正式证据。

## 后果

- 会话页面需要维护路径模式、帮助使用记录和折叠提示；旧草稿必须通过新的存储前缀隔离，不能与新教学模型混用。
- 检查器继续验证可执行行为，但提交内容还要说明学习者看过哪些帮助以及哪些结构可以迁移。
- 阶段 A 可以更快恢复代码所有权；阶段 B–D 仍负责方案比较、约束变化、模型建立、反例处理和开放式迁移。
- 逐行注释需要区分“责任解释”和“语义答案”，避免注释数量增加后反而变成不可见的答案键。
