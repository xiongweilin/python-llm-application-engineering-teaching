# 0002：阶段 A 采用示范优先、局部补全、有限迁移

## 状态

已接受，2026-08-18。

## 背景

正式学习会话 2 原本把失败重试、操作身份、批处理、异常契约和边界迁移放在同一会话中，并要求学习者在解释之后直接补全多个近乎空白的函数。这样的页面结构看似有七步闭环，但第一次接触时仍需要学习者自行组合尚未稳定的概念，容易把“不会设计”误判为“没有学会”。

课程的近期目标是取得真实 Python 代码的所有权：能够读懂输入、输出和控制流，跟随示范修改局部代码，运行检查，并解释一个小变化的结果。独立建模、方案比较、反例构造和开放式迁移属于后续数学、Agent、评估和综合项目阶段，不能提前变成阶段 A 的隐含门槛。

## 决定

阶段 A 的正式会话统一采用以下教学坡度：

```text
教师示范 → 共同追踪输入/输出 → 局部补全 → 运行检查 → 一个有界变化 → 解释稳定结构
```

具体规则：

1. 每个新问题必须先提供具体输入、输出、执行轨迹或完整小例子；不能只给术语、规则和空白函数。
2. 核心代码任务使用近完整脚手架，明确指出需要修改的位置；局部补全优先于从空白设计。
3. 迁移任务只改变一个明确条件、常量、分支或返回契约；需要重新选择模型或设计完整接口的任务后移。
4. 早期阶段可以保留预测和解释，但预测建立在已展示的执行轨迹上，解释使用句式、表格或局部提示支撑。
5. 自动检查用于反馈局部行为；是否形成能力记录仍需要说明、修改、诊断或迁移证据。
6. 阶段 A 的可见 Python 示范和起始代码逐行旁注，旁注解释对象、输入/输出、控制流、副作用和放置原因；它们不只重复语法名称。

## 未采用的方案

- **继续保留空白实现和开放迁移：**会把设计能力缺口混同为基础代码能力缺口，违反当前学习目标。
- **完全删除预测和迁移：**会失去对控制流和条件变化的最小验证；因此保留它们，但把范围限制在已示范结构内。
- **把所有思维训练推迟到课程末尾：**基础阶段仍需要解释执行顺序和局部因果关系；推迟的是开放式建模和方案选择，而不是取消理解。

## 后果

- 正式会话的七步名称和九项任务数量可以保留，但每一步的证据坡度必须符合当前阶段。
- 会话页面需要维护示范轨迹、近完整代码和明确改动标记；不能只依赖检查器和自由文本框。
- 代码旁注成为页面的一部分，避免学习者在说明页、示范页和代码编辑器之间来回寻找同一行的责任解释。
- 阶段 A 的关口表述应强调“在脚手架下可靠修改和诊断”；更大范围的独立跨模块实现由后续关口承担。
- 阶段 B–D 再逐步增加模型建立、参数变化、方案比较、机制分析、因果判断和开放迁移。
